"dsh-mnemon": patch

Git sync over HTTPS uses the token you gave it, or your GitHub sign-in, on a computer whose Git configuration names a user for the host or turns on `credential.useHttpPath`, as Git Credential Manager setups do; before, Git looked the token up under that name or path, found nothing, and the page asked for credentials that were already there. An address that writes its host in capitals or with its port, such as `https://GitHub.com:443/...`, finds its token now too. gitee.com, which refuses `x-access-token`, is offered the token under `oauth2` (Gitee requires it or the account name); every other host keeps `x-access-token`, and a host that wants another name, such as Bitbucket or a self-hosted Gitee, takes it in the address, as in `https://x-token-auth@bitbucket.org/...`, while a password or a token in the address is still refused. An earlier dsh-mnemon refuses a saved address that names a user, even to change or disconnect it, so remove the name before going back to one. When the host rejects a credential it was offered, the sync settings now say so and name it, the GitHub sign-in, the saved token or `MNEMON_SYNC_GIT_TOKEN`, instead of asking you to sign in or add a token.
