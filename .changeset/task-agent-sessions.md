Memory tasks no longer leave empty conversations in DSH. Every memory task that runs outside a conversation runs under a task Agent whose session DSH keeps: Save to memory, Ask Agent, Document archive, a new Memory Space's Provider choice, Tidy names and descriptions, runtime memory capacity maintenance (which also condenses a full user profile before Save to memory adds to it) and memory reconciliation. dsh-mnemon now creates that session with the origin DSH gives its own subagents, so neither the DSH sidebar nor the ACP session list shows it as a conversation. Before, wherever DSH held no projection-cache record of such a session, the sidebar listed it as an empty Untitled conversation under Ungrouped, one more for every task, and ACP editors listed it on any host (#435). The tasks run and report as before, on DSH 0.2.0 and 0.2.1. For plugins that read session logs, the task Agent session now has `origin: "subagent"` and no parent, as the Delegated child sessions section of the workflows reference describes. Rows earlier releases left stay until you archive them with Archive session; memory data is unaffected.
