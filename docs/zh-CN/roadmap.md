# 路线图

**简体中文** | [English](../en/roadmap.md) | [文档中心](./README.md)

本页区分已交付基础和剩余工作。未来条目是方向，不是版本承诺。

## 已交付的基础

- 独立 Source、Strategy、Provider 包，小型公共贡献服务、Source 自有页面，以及每个执行回合唯一的不可变 View。
- 以分层策略为默认主策略、通用策略为可选主策略的 Starter，以及可与任一主策略配合的三个可选增强。
- Source 内部的 Provider 描述符、连接 schema、脱敏和子 Fiber 注册。
- 公开契约测试、仓库外独立制品验证、隔离 Headless/WebUI 夹具，以及选择性包发布。

实际范围和限制见[架构](./development/architecture.md)、[开发与验证](./development/README.md)与[发布流程](./development/releasing.md)。

## 下一步：可靠性与恢复

- 持久化空闲审查水位与待处理活动，重启后恢复，并增加有界退避和显式重试。
- 完善整理中断时的幂等和取消，保留部分写入及 Source 修订证据。
- 在记忆准入前增加确定性的敏感内容防线；现有模型指引不是秘密扫描器。
- 扩展真实 WebUI 与故障注入覆盖：范围、并发编辑、容量、远端部署路径、Provider 恢复和受支持 OS 组合。
- 扩展[已验证兼容矩阵](./reference/compatibility.md)，包括明确授权的真实 Provider 测试；适配器夹具并不足够。

## 下一步：2026 年 10 月审查发现的问题

v0.5.31 之后的一次代码审查发现了以下具体问题。每一项都会改变用户、插件作者或模型看到的内容，因此各自单独提交 PR。[计划](../plans/review-gaps-2026-10.md)（英文）按同样的顺序逐项记录了现状和拟议的改法。

- **备份与 Git 同步保留 Native 空间的放置决定。** 包含记忆空间的导入以及基于导入的同步只保留每个记忆空间条目的六个字段，Native 空间因此丢失已记录的自动放置决定。
- **所有存储使用同一种原子写入和同一条锁规则。** 11 处手写的原子写入在失败后留下什么、临时文件如何命名上各不相同；四种锁实现中只有一种会在删除锁之前确认锁仍归自己所有。
- **Provider 设置中已保存凭证的统一规则。** 在记忆空间的“记忆 Provider”设置中，删掉已保存凭证掩码的一部分再保存，会把剩下的掩码字符保存为新凭证。这里也应采用对话框的规则：留空即保留已保存的凭证，清除需要明确操作。
- **Mnemon 调用超时使用同一个范围。** 同一个值，Host 接受 100–120,000 毫秒，记忆空间 Source 接受 1–600,000 毫秒；统一之后，超出范围的已保存值应在读取时限制在范围内，而不是被拒绝。
- **回合记忆栏打开处理该工具调用的 Source 的页面。** 目前记忆栏不认识的工具（包括通用 View 工具），以及来自其他 Source 的条目，都会打开记忆空间。
- **具名记忆工具只传递 Source 接受的参数。** 模型额外加上的属性、超过 20 的召回 `limit`，或通过 `mnemon_view_action` 传入的带小数的 `importance`，都可能让 Source 拒绝一次工具 schema 允许的调用。
- **Provider 自带翻译文案**；没有文案的 Provider 显示自己的简介，而不是一行空白。
- **记忆空间通过 Provider 适配器访问 Mnemon Native**，用于嵌入状态与补齐、版本检查和空间合并，使其他 Provider 也能提供同样的操作。
- **为每个 Source 和 Provider 都在重复的代码提供 SDK 辅助函数**：页面呈现、修订变化时刷新、导航种子，以及带默认状态检查的 Provider 包入口。

## 后续：受控整理与扩展成长

- 可审阅的跨会话长期整理、冲突与衰减候选，以及明确执行的遗忘。
- 更完整的多组件备份/恢复演练，损坏元数据和缺失投影的修复工具。
- 在持久格式确需改变时提供明确的数据迁移和回滚流程。
- 更清楚的空闲审查历史与诊断，以及 Host 错误和命令输出的国际化。
- 在 DSH 提供相应能力后复用通用目录选择器，跟踪 [dsh-external/issues#603](https://github.com/dsh-external/issues/issues/603)（私有仓库，需具备访问权限；未登录时返回 404）。
- 为 RSI 提供候选 Source/Strategy 评估与受控晋升：保留输入、制品、权限及对照结果，再明确决定安装。

## 保持的边界

当前 UI 表达记忆行为，不提供通用插件市场或 View 画布。外部插件遵循 DSH 安装流程与公开作者契约。

Cordis 归属不是沙箱。当前不自动执行模型生成代码，不承诺通用删除、跨 Provider 事务、主动通知守护进程，或无需适配即可接入所有三方记忆插件。
